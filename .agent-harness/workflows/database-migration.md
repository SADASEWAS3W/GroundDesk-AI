# 数据库迁移工作流

本工作流属于 L3。

验证时机遵循 `../rules/verification-rules.md`：内部阶段只准备测试和待验证项，整项任务实现完成后，在同一轮执行步骤 5～7 的集成检查与步骤 9 的门禁。操作前的目标核对、授权、备份及方案审查不得延后；正式数据迁移不能先执行后验证安全前置条件。

1. 说明 Schema 变化、影响行数、锁表/运行风险和回滚策略。
2. 破坏性操作或批量转换前备份重要数据。
3. 新增有序迁移；未经批准不得改写已部署迁移。
4. 尽量拆分结构迁移和大规模数据回填。
5. 全部实现和文档完成后，在最终验证轮次测试空数据库和上一版本数据库升级。
6. 验证幂等性；非幂等迁移必须明确标记为一次性。
7. 检查行数、空值、索引、向量维度和外键完整性。
8. Embedding 变化时使用同一模型重建全部向量，并只清理相关缓存命名空间。
9. 同一最终轮次运行后端、Embedding、密钥和完整 Compose 门禁，与 Profile 检查去重。
10. 记录恢复命令，但验证阶段不得执行破坏性回滚。
