# 双人开发协作规则

## 事实边界

- 不得编造、猜测或默认另一位开发者已经完成、接受或正在实现任何接口、字段、流程或文件修改。
- 只有仓库中的已提交代码、可读取的工作区改动、实际测试结果、运行结果，或用户明确转述的开发者反馈，才能作为已确认事实。
- 计划文档、建议方案、Mock、Protocol 和示例代码只代表提案，不代表另一位开发者已经同意或完成接入。
- 汇报时必须明确区分“已验证事实”“基于证据的推断”和“等待开发者确认的事项”。无法验证的内容必须标记为待确认。

## 必须通知用户的交互点

出现以下任一情况时，Agent 必须在继续修改共享边界前通知用户，并明确列出需要开发者 B 确认的问题：

- 修改或依赖共享 State、Graph State、API Request/Response 或事件结构；
- 确定 LangGraph 如何创建、注入或调用 Retrieval Service；
- 修改 Citation 字段、编号、展示或来源校验职责；
- 确定检索失败、低置信度、Grounding 和 HITL 之间的路由规则；
- 修改双方都可能编辑的共享文件或数据库迁移；
- 需要开发者 B 接入、联调、评审或确认兼容性；
- 现有代码和文档无法证明另一位开发者的实际实现状态。

通知内容至少包括：

```text
需要确认的事项：
为什么需要开发者 B：
当前已确认事实：
不能确认的部分：
建议的接口或选项：
如果暂不确认，可以继续进行的独立工作：
```

## 停止边界

- 在开发者 B 尚未确认时，可以继续完成不改变共享契约的独立模块、Fake、测试和文档。
- 不得以“先假定 B 会这样实现”为理由修改共享契约或宣称联调完成。
- 如果继续实现会固化双方接口、造成合并冲突或改变 B 的职责范围，必须暂停该部分并等待用户反馈。
- 用户可以明确授权采用某个临时契约；此时必须记录该契约是用户授权的临时决定，而不是开发者 B 已确认的事实。

## 验收与汇报

- “接口已定义”不等于“接口已由开发者 B 接受”。
- “Fake 联调可用”不等于“真实 LangGraph 已接入”。
- “单侧测试通过”不等于“双人集成通过”。
- 只有实际执行双方集成路径并获得可验证结果后，才能声称联调完成。
