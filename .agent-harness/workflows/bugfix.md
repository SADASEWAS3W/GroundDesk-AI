# Bug 修复工作流

验证时机遵循 `../rules/verification-rules.md`：复现和定位允许最小诊断，不要求每个修复阶段运行回归或完整门禁。

1. 复现实际行为，记录预期结果与实际结果。
2. 确认问题所属层，并在修改前检查相邻调用方。
3. 判断风险；涉及 Agent 路由、RAG、数据库、安全或部署时升级为 L3。
4. 新增或修改一个能够复现问题的回归测试。
5. 只实现必要修复，不进行无关重构。
6. 完成全部修复及说明文档，汇总受影响测试和任务配置要求的 Harness 门禁。
7. 最终交付前统一运行一轮去重检查，包括测试、门禁和 `git diff` 范围审查，保护用户既有改动。
8. 汇总根因、修复摘要、验证证据和剩余风险；失败修复后只补验失败项与受影响项。

提交格式：`fix: 简短修复说明`。
