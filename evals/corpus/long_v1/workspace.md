# Workspace Projects and Tasks Handbook

## Start with an account and a workspace

Create an account at app.example.com/signup using your work email. After verifying the email address, continue through the onboarding wizard. The wizard walks through creating a first project, inviting team members, and configuring workspace settings. The introductory guide describes the overall process as taking about 5 minutes. That is an approximate onboarding description rather than a deadline for every individual task.

The account, workspace, project, and task are useful distinctions when asking for help. Onboarding introduces the initial working environment, while projects organize work and task boards hold individual items. A question about the first invitation is different from a question about moving an existing task between columns. State the level you are working at so that the instructions can address the correct operation.

## Create a project deliberately

To create a project, click the '+' button on the dashboard. Choose a template or start from scratch, then give the project a name and description and assign a team. The template choice and the descriptive fields serve different purposes: the choice establishes a starting point, while the name and description explain what the project is for. A clear description is useful when multiple projects have similar names.

Projects can be organized into folders for better structure. As a practical organization habit, use the description to explain the work's purpose and folders to keep related projects together. This advice does not introduce additional project permissions or automated rules. It simply uses the organization features already described in the project guide.

## Understand the task board

Each project contains a task board with customizable columns, such as To Do, In Progress, and Done. The example column names illustrate a workflow and are not the only possible arrangement. Create a task by clicking '+ Add Task' in any column. Select the column that represents the intended initial status so that the item appears in a useful place on the board.

Tasks support descriptions, due dates, assignees, labels, attachments, and sub-tasks. These fields describe different aspects of the work. A description explains the requested outcome, an assignee identifies responsibility, and a due date records timing. Labels, attachments, and sub-tasks provide additional organization and detail. A practical task-writing habit is to make the expected outcome clear before adding supporting material.

## Keep work discoverable as the project grows

Drag and drop tasks between columns to update their status. Moving a task changes its position in the workflow represented by the board. It should not be confused with archiving the entire project, which is a separate project-level operation. When discussing a status problem, identify the task and the columns involved rather than describing the whole project as missing.

Use filters and sorting to find tasks quickly in large projects. Before assuming an item is absent, consider the view being used to locate it. Filtering and sorting are ways to navigate the task board; they are not documented here as a data-export or deletion mechanism. This distinction matters when a support conversation moves between finding work and removing work.

## Finish a project without confusing archive and deletion

Archive completed projects from the project settings menu. Archived projects remain accessible and do not count toward plan limits. Archiving therefore has a different meaning from permanently deleting an account or its data. A completed project can leave the active workflow without the project guide describing it as permanently erased.

For example, after a team finishes a project, it can review the task board and use the project settings menu to archive the project. The access and plan-limit behavior comes from the archive rule, not from dragging the last task into Done. Completing tasks and archiving the project are separate actions in this workflow.

When requesting help about completed work, specify whether the task was moved to a completed column or the project itself was archived. Include the project name and the observed operation, but avoid attaching unnecessary private task contents. This provides context for troubleshooting without changing the meaning of the project's documented archive behavior.
