# 功能开发工作流

验证时机遵循 `../rules/verification-rules.md`：以下步骤覆盖整个用户任务，内部阶段不重复执行验收。

1. 定义用户目标、非目标、所属层和公开契约。
2. 从 `task-workflow-profiles.json` 选择 Profile 和 Lane。
3. L3 改动必须先完成方案审查。
4. 跨层连接前，先定义接口并补充测试。
5. 按依赖方向实现：领域/检索 → Agent/Application → API → Web。
6. 环境变量变化时同步更新示例配置和部署清单。
7. 完成所有阶段，更新使用方法、已知限制和回滚说明，汇总待验证项。
8. 最终交付前统一执行一次去重后的 Profile 门禁；跨层功能的端到端冒烟测试纳入同一轮，记录结果。

提交格式：`feat: 简短功能说明`。
